### РЕШЕНИЕ (2026-09-08): исправлено в mission-sender.js

Разбирали вживую (формы floten1–3, безопасные тесты с 10–100 линкорами):

1. **Кнопка «max» на сервере НЕ РАБОТАЕТ** — JS-функции maxResource()/maxResources()
   на стадии 3 НЕ ОПРЕДЕЛЕНЫ (в HTML только getStorageFaktor). Бот теперь сам
   воспроизводит «max» из hidden-полей thisresource1/2/3: заполнить ВСЁ доступное
   (алмазы, уран − несгораемый keep, металл), при избытке — пропорционально
   ужать до вместимости. Урана меньше keep → взять 0 (несгораемый остаётся).
2. **Вместимость сервера МЕНЬШЕ суммы из формы** ship×capacity (10 линкоров:
   форма 15300, сервер 15201; 100 линкоров: форма 153000, сервер 152019).
   Ошибка «Недостаточно места для погрузки: N» содержит ТОЧНЫЙ избыток
   (вместимость = отправлено − N). **Исправление: цикл коррекции** — первая
   попытка по оценке вместимости; при избытке N стадии 1–3 повторяются с точной
   вместимостью (отправлено − N − 1), до 3 попыток. Флот ВСЕГДА улетает.
3. **В URL стадии 1 нужен mode=3** — без него на теле-источнике (fromCp)
   форма floten1 может не иметь полей ship<ID> (проверено: луна 1:918:1).
4. Live-тест (10 линкоров → луна 1:918:1): попытка 1 (15299) → избыток 98,
   попытка 2 (15199) → УСПЕХ, 4.3 с. Флоты теста возвращены домой.
