# PLAN.md — аудит и план доработки serverXG

Дата аудита: 19.08.2025 (поверхностный обзор ключевых файлов)

## Вердикт: готов ли проект?

**Не готов к стабильной работе.** Это рабочий прототип:

- ✅ Работает: аутентификация (`session-manager.js` — логин с ретраями, сохранение cookies, проверка сессии), структура проекта, базовый запуск `node serverXG.js`.
- ❌ Не работает (или работает «вслепую»): вся цепочка автозапуска экспедиций. Есть 4 критических бага, из-за которых бот **никогда не отправит экспедицию**.
- 🔴 Критично: в git закоммичены живые креды и cookies.

## Критические баги (P0 — бот не работает)

### 1. `app/expedition.js` читает удалённый `config_one.json`
```js
const configPath = path.join(__dirname, "..", "config_one.json");
```
Файл удалён из working tree (в git он есть, в файле — старые координаты `3-534-9`, `3-257-5`).
Чтение находится **вне try/catch** → `ENOENT` летит в `watchMissions` → бот каждые 30 сек пишет ошибку и не запускает экспедиции вообще.
**Фикс:** читать `config.json` (там актуальный массив `expeditions`), вынести чтение в try/catch.

### 2. `app/expedition.js` — неопределённые переменные `ships`, `from`, `to`
```js
console.log(`  - Корабли: ${ships.join(", ")}`);  // ships не объявлена
console.log(`  - Откуда: ${from}`);               // from не объявлена
console.log(`  - Куда: ${to}`);                   // to не объявлена
```
→ `ReferenceError` на первой же координате → ловится внешним try/catch → **весь цикл экспедиций прерывается**.
**Фикс:** собрать реальные значения (список выбранных кораблей из floten1, координаты отправления из hidden-полей) или убрать лог.

### 3. Потеря cookies между `ensureLoggedIn` и `watchMissions`
- `isLoggedIn()` создаёт **новый** context, проверяет сессию и **закрывает его**.
- `watchMissions()` берёт `browser.contexts()[0]`. Если сессия восстановлена из `session.json` (а не свежий логин), открытых контекстов нет → создаётся **пустой** context без cookies → бот работает неавторизованным (страницы редиректят на login.php).
- Работает только «на счастливый случай» — когда только что выполнен `doLogin` (default context жив).
**Фикс:** единый context на всё приложение: создать один раз в `serverXG.js`, загрузить в него cookies, передать в `ensureLoggedIn`/`watchMissions`/`startExpedition`.

### 4. `watchMissions` парсит пустую страницу
- После `doLogin` страница закрыта → `context.pages()[0]` undefined → создаётся blank-страница.
- `page.reload()` на `about:blank` → regex `Флоты: X / Y` и `Экспедиции: X / Y` никогда не сработают → слоты всегда `"?"` → `parseInt("?")` = `NaN` → `NaN < NaN` = `false` → `startExpedition` **никогда не вызывается**.
**Фикс:** явно навигировать на страницу со статистикой (overview.php / fleet.php, см. `debags/*.html` — там реальная структура), парсить слоты по DOM (hidden-поля `maxepedition`/`curepedition` уже известны из `test-expedition.js`), а не по regex текста.

### 5. Формат координат не сходится
- В `config.json`: `"1:260:9*"` (со звёздочкой).
- `formattedCoord.replace(/-/g, ":")` звёздочку не режет → поиск `a.innerText.includes("1:260:9*")` в overview всегда фейлится → `cpId = null` → все координаты пропускаются.
- `split(":")` даёт `["1","260","9*"]`, код берёт только `[gal, sys]` и хардкодит `planet=16` — третья часть координаты (планета 9) игнорируется.
**Фикс:** нормализовать координаты (`replace(/[*-]/g,"")` → split на 3 части), цель = `gal:sys:planet` из конфига, а не хардкод 16; либо явно задокументировать, что «16» — осознанный выбор.

## Безопасность (P0/P1)

### 6. В git закоммичены секреты
Трекуются: `config.json` (ник+пароль), `config_one.json` (то же), `session.json` (живые cookies), а в untracked — `user.md` с теми же кредами.
**Фикс (порядок важен):**
1. Сменить пароль в игре (и удалить/обновить `session.json`).
2. `git rm --cached config.json config_one.json session.json user.md`, добавить в `.gitignore`: `config.json`, `config_one.json`, `session.json`, `user.md`, `debags/`, `debug-*.html`.
3. Оставить шаблон `config.example.json` без реальных данных.
4. Если репозиторий когда-либо публиковался — чистить историю (`git filter-repo`) или завести новый репозиторий.

### 7. Креды в двух местах
Пароль дублируется в `config.json` и `user.md`. Оставить только `config.json` (вне git), `user.md` удалить.

## Архитектура и качество (P1)

### 8. Единый источник конфига
`session-manager.js` читает `config.json`, `expedition.js` — `config_one.json`. Создать `app/config.js` (модуль-экспорт) — один файл, одна точка чтения.

### 9. Обработка просрочки сессии в долгом цикле
Если сессия «умрёт» во время работы, `watchMissions` будет вечно гонять login-страницу. Добавить в цикл: детект `login.php` в URL → вызов `ensureLoggedIn` → продолжить.

### 10. Корректное завершение
- `serverXG.js`: `await new Promise(() => watchMissions(browser))` — promise никогда не резолвится, ошибки глотаются. Сделать `watchMissions` останавливаемым (флаг/AbortController).
- Обработчики `SIGINT`/`SIGTERM`: закрыть браузер, сохранить сессию, `process.exit(0)`.

### 11. Логи
- `console.clear()` в цикле мешает при запуске в фоне (pm2/nohup). Заменить на файл-лог (`logs/bot-YYYY-MM-DD.log`) + опциональный вывод в консоль.
- Вынести таймауты и интервал поллинга (30 c, 1.5 c) в конфиг.

### 12. Устаревшие API
`page.waitForNavigation` deprecated в Playwright 1.59 — заменить на `page.waitForURL` / `page.waitForLoadState`.

### 13. Чистка «временного»
`analyze-run.js`, `test-expedition.js`, `app/analyze-pages.js` помечены как временные, но лежат в корне. Перенести в `scripts/dev/` или удалить (их задача — сбор debug-HTML — выполнена, результаты в `debags/`).

### 14. README
Документ **дублируется** (весь текст повторяется дважды), устарел (указывает `analyze-run.js` как точку входа, противоречивый раздел «Использование»). Переписать: одна секция, актуальный вход `node serverXG.js`, описание конфига, предупреждение про секреты.

### 15. Прочее
- `debags/` — опечатка (debugs), в git не трекается; переименовать в `debug/` и игнорировать.
- `package.json`: `test` — заглушка; добавить `npm run analyze`, `npm run test:expedition` (если скрипты оставляем).
- `expedition.js`: «Взять все корабли» без логики выбора — забирает всё, включая корабли, которые могут понадобиться для атак/перевозок. Минимум — вычитать список из floten1 и логировать, что именно улетело (закроет баг №2).
- Анти-бан: пауза 1.5 c фиксированная; добавить рандомизацию (1–4 c) и лимит отправок за цикл.
